# 포인트 충전 API 부하 테스트 계획서
## 1. 테스트 개요
### 1.1 테스트 목적
- 포인트 충전 API(`POST /api/v1/users/{userId}/points`), 주문 생성 API(`POST /api/v1/orders`), 결제 API(`POST /api/v1/orders/{userId}/payments`)의 성능 및 안정성 검증
- 높은 동시 사용자 부하 상황에서의 시스템 응답 시간 및 처리량 측정
- 시스템의 임계점 파악 및 성능 병목 구간 식별

### 1.2 테스트 대상
- **API 엔드포인트**
  - `POST /api/v1/users/{userId}/points`
  - `POST /api/v1/orders`
  - `POST /api/v1/orders/{userId}/payments`
- **서버 환경**: `Local`
- **테스트 도구**: K6

## 2. 테스트 시나리오
### 2.1 부하 패턴
점진적 증가 부하 테스트를 통한 성능 검증

### 2.2 테스트 데이터
#### 2.2.1 포인트 충전 테스트 데이터
- **사용자 수**: 총 2,000명
- **충전 금액**: 1,000원 고정
- **사용자 선택**: 랜덤 선택 방식

#### 2.2.2 주문 생성 테스트 데이터
- **사용자 수**: 총 2,000명
- **상품 수**: 총 416개 상품
- **주문 상품 수량**: 1~5개 상품 (랜덤)
- **상품별 수량**: 1~5개 (랜덤)
- **상품 가격대**: 1만원, 2.5만원, 5만원, 7.5만원, 10만원 (각 20% 비율)
- **배송 주소**: 5개의 서울시 주요 지역 주소 (랜덤 선택)
- **수령인 전화번호**: 5개의 테스트용 전화번호 (랜덤 선택)

#### 2.2.3 포인트 결제 테스트 데이터
- **사용자 수**: 총 2,000명
- **결제 방법**: POINT 고정
- **ID 관리 방식**: VU별 고유 ID 할당으로 중복 방지
